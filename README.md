# Ask Your PDFs (RAG)

A small Retrieval-Augmented Generation app: it indexes a folder of PDFs and answers questions about them with page-level citations like `[nist-ai-rmf.pdf, p. 25]`. If the answer is not in the documents, it says **"I don't know based on the provided documents."**

```
                 ingest.py                                       ask.py / app.py
PDFs ─► text per page ─► overlapping chunks ─► embeddings ─► Chroma ─► hybrid search ─► rerank ─► LLM ─► answer + [file, p. N]
       (pypdf)          (~800 chars, 150 overlap)  (bge-small)          (vector + BM25)  (cross-   (Gemini / OpenAI / Claude)
                                                                                         encoder)
```

The same search is available to AI agents through an **MCP server** ([below](#use-it-from-an-ai-agent-mcp)), and an **evaluation script** measures retrieval and answer quality on a fixed question set ([below](#evaluation)).

## Tech stack

| Part | Choice | Why |
| --- | --- | --- |
| PDF → text | `pypdf` | Pure Python, gives text page by page, so every chunk knows its page number. |
| Embeddings | `sentence-transformers` with `BAAI/bge-small-en-v1.5` | Small (33M params), runs on CPU, much better retrieval than `all-MiniLM-L6-v2` (that model could not match "SBERT" to the Sentence-BERT paper). |
| Vector store | Chroma (persistent, local folder `chroma_db/`) | No server needed; stores text + `source` + `page` metadata. |
| Keyword search | BM25, implemented in [rag/store.py](rag/store.py) | Catches passages that hinge on an exact term, which embeddings rank too low. |
| Reranker | `cross-encoder/ms-marco-MiniLM-L-6-v2` | Reads the question and each candidate together; ~0.3 s per question on CPU. Lifted the evaluation from 5/6 to 6/6. |
| LLM | Gemini, OpenAI or Anthropic — whichever API key is set | Gemini has a free tier. |
| UI | CLI (`ask.py`), Streamlit web UI (`app.py`), MCP server for AI agents (`mcp_server.py`) | |

## Setup

Requires Python 3.10–3.12.

```bash
python -m venv .venv
# Windows (PowerShell):  .venv\Scripts\Activate.ps1
# macOS / Linux:         source .venv/bin/activate
pip install -r requirements.txt
```

Copy `.env.example` to `.env` and set **one** API key (e.g. `GEMINI_API_KEY`, free at <https://aistudio.google.com/apikey>).

Build the index (first run downloads the ~130 MB embedding model):

```bash
python ingest.py
```

```
  chain-of-thought.pdf: 43 pages -> 230 chunks
  nist-ai-rmf.pdf: 48 pages -> 192 chunks
  self-rag.pdf: 30 pages -> 179 chunks
  sentence-bert.pdf: 11 pages -> 73 chunks
Indexed 674 chunks from 4 PDFs into ...\chroma_db
```

To use your own documents, put PDFs into `pdfs/` (or set `PDF_DIR`) and run `python ingest.py` again; it rebuilds the index from scratch.

## Asking questions

CLI, one question:

```bash
python ask.py "What are the four functions of the AI RMF Core?"
```

```
The four functions of the AI RMF Core are GOVERN, MAP, MEASURE, and MANAGE [nist-ai-rmf.pdf, p. 25].
```

CLI, interactive mode: `python ask.py`. Add `--show-context` to see the retrieved chunks and their similarity scores, `-k 8` to retrieve more chunks.

Web UI:

```bash
streamlit run app.py
```

Opens <http://localhost:8501> with a question box, a top-k slider and an expandable list of the retrieved excerpts.

## How it works

**Ingestion** ([rag/ingest.py](rag/ingest.py))
1. Each PDF page is extracted separately with pypdf and cleaned: Unicode NFKC (turns ligatures like "ﬁ" into "fi"), words hyphenated at line ends are re-joined, whitespace is collapsed.
2. Each page is split into chunks of ~800 characters on sentence boundaries; every chunk starts with the last ~150 characters of the previous one (overlap), so a sentence cut at a chunk border is still found. Chunks never cross pages, so each chunk has exactly one page to cite.
3. Chunks are embedded with bge-small (normalized vectors) and stored in Chroma with metadata `{source: filename, page: N}`.

**Retrieval** ([rag/store.py](rag/store.py)), in three steps:
1. *Semantic search*: the question (with bge's query instruction prefix) is embedded and the closest chunks by cosine similarity are taken.
2. *Keyword search*: BM25 over the same chunks, so a passage that contains the exact words of the question is found even if its embedding is not close.
3. *Reranking*: the candidates from both are scored by a cross-encoder, which reads the question and the passage together, and the top-k (default 5) are kept.

`SEARCH_MODE` switches between `vector` (step 1 only), `hybrid` (steps 1 + 2 merged with reciprocal rank fusion) and `rerank` (all three, the default).

**Generation** ([rag/answer.py](rag/answer.py))
- Each chunk goes into the prompt with a header like `### Excerpt 2 [self-rag.pdf, p. 1]`. The system prompt tells the model to use only those excerpts, end every factual sentence with a citation copied from a header, and reply with the exact "I don't know..." sentence when the excerpts don't contain the answer.
- "I don't know" has two layers: if even the most similar chunk has similarity below `MIN_SIMILARITY` (0.5), the LLM isn't called at all; otherwise the LLM decides based on the prompt rules.
- Citations in the answer are checked against the retrieved chunks; a citation that wasn't retrieved (hallucinated) is shown as a warning.

## Use it from an AI agent (MCP)

[`mcp_server.py`](mcp_server.py) exposes the documents to any [MCP](https://modelcontextprotocol.io) client, so an agent can look things up in your PDFs while it works:

| Tool | What it returns |
| --- | --- |
| `list_documents` | indexed files and their chunk counts |
| `search_documents(query, k)` | the most relevant excerpts with `[file, p. N]` citations and similarity scores. No API key needed: the agent reads the excerpts and answers itself. |
| `ask_documents(question, k)` | a grounded answer with citations, the citation check and the excerpts it was based on, or "I don't know" |

All three are marked read-only. Register the server with **Claude Code**:

```bash
claude mcp add ask-your-pdfs -- /path/to/ask-your-pdfs/.venv/bin/python /path/to/ask-your-pdfs/mcp_server.py
```

or in **Claude Desktop** (`claude_desktop_config.json`; on Windows the interpreter is `.venv\Scripts\python.exe`):

```json
{
  "mcpServers": {
    "ask-your-pdfs": {
      "command": "/path/to/ask-your-pdfs/.venv/bin/python",
      "args": ["/path/to/ask-your-pdfs/mcp_server.py"]
    }
  }
}
```

Run `python ingest.py` first, and restart the server after re-ingesting.

## Evaluation

[`evaluate.py`](evaluate.py) runs the questions in [`eval/questions.json`](eval/questions.json) and exits non-zero if any check fails, so it can guard changes:

```bash
python evaluate.py                 # retrieval only: fast, free, no API key
python evaluate.py --llm           # also generate the answers and check them
python evaluate.py --mode vector   # compare search modes
```

For answerable questions it checks that the passage with the answer is among the top-k excerpts (**hit@k**; **MRR** of 1.0 means it was always ranked first). With `--llm` it also checks that the answer cites an expected page, mentions the key facts and cites nothing that wasn't retrieved. Unanswerable questions must get the exact "I don't know" reply.

Retrieval on the sample corpus (top-5):

| Search mode | hit@5 | MRR |
| --- | --- | --- |
| `vector` (embeddings only) | 5/6 | 0.75 |
| `hybrid` (+ BM25, rank fusion) | 5/6 | 0.83 |
| `rerank` (+ cross-encoder, default) | **6/6** | **0.92** |

With `--llm` (Gemini 3.6 Flash, `rerank`): all 6 answers cite an expected page, contain the key facts and have no made-up citations, and all 3 unanswerable questions are refused (one by the similarity threshold, two by the LLM).

What the evaluation caught: semantic search alone never found the sentence "The default configuration is MEAN" (it isn't even in the top 30), so the SBERT pooling question got "I don't know". Keyword search ranks that chunk first and the reranker keeps it at the top. It also showed that the citation this README used to list for that question (p. 4) was wrong: the sentence is on p. 3.

Six questions are a small set. It catches regressions and obvious gaps, but the numbers are not a benchmark.

## Tests

```bash
pip install pytest
pytest
```

Unit tests cover cleaning and chunking, BM25 ranking, and citation extraction and checking. They found one bug: on long table rows a chunk could exceed the size limit by up to the overlap length (16 of 674 chunks, up to 947 characters); now fixed. [`tests/test_mcp_server.py`](tests/test_mcp_server.py) starts the MCP server over stdio and calls its tools through a real MCP client.

## Project structure

```
ingest.py          build the index:   python ingest.py
ask.py             CLI:               python ask.py "question"
app.py             web UI:            streamlit run app.py
mcp_server.py      MCP server:        python mcp_server.py (started by the AI client)
evaluate.py        quality check:     python evaluate.py [--llm] [--mode vector|hybrid|rerank]
eval/questions.json  evaluation questions with expected pages and key facts
tests/             unit tests + an MCP client test:   pytest
rag/config.py      settings (paths, models, chunk size, top-k, search mode, threshold)
rag/ingest.py      PDF -> chunks -> Chroma
rag/store.py       embeddings, Chroma, BM25, hybrid search, reranking
rag/answer.py      prompt, LLM call, citations
rag/llm.py         Gemini / OpenAI / Anthropic client
pdfs/              sample documents
```

## Limitations

- Scanned PDFs (images without a text layer) are skipped; they would need OCR.
- Tables and figures come out of pypdf as flat text, so numbers inside charts are retrieved less reliably.
- The similarity threshold is tuned for bge-small; with another embedding model, check the scores with `--show-context` and adjust `MIN_SIMILARITY`.
